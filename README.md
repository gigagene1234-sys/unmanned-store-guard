# StoreGuard Hub v0.1.0

무인가게에서 **DMSS**와 **안시포스 식음 ASP**를 기존 그대로 사용하면서, 필요한 이벤트/거래 정보만 별도 로컬 DB로 수집하는 Android 기반 관리 허브의 1차 구현입니다.

## v0.1 범위

- DMSS(`com.mm.android.DMSS`) 알림 이벤트 자동 수집
- 안시포스 식음 ASP(`com.annecypos.foodasp`) 화면의 거래 행 자동 읽기
- 거래일자, 초 단위 승인시각, 결제수단, 정상/취소 상태, 금액 저장
- 중복 거래 저장 방지
- CCTV/POS 시간 오프셋 저장 및 표본 기반 추천
- 최근 수집 결과/로그를 앱 대시보드에서 확인
- DMSS/안시포스 앱 바로 열기
- 데모 데이터로 설치 직후 동작 확인

## 의도적으로 아직 포함하지 않은 것

v0.1은 **방문자의 신원 식별, 얼굴 인식, 절도 확정, CCTV 영상의 상시 화면 캡처**를 하지 않습니다. 먼저 실제 기기에서 두 앱의 데이터 수집과 시간 동기화를 검증합니다.

다음 버전의 예정 모듈은 서로 분리합니다.

1. Visitor tracking: 한 번의 방문 세션 동안만 익명 Visitor ID 유지
2. Payment linking: 결제 이벤트와 방문자/결제행동 연결
3. Anomaly analysis: 결제 유무와 독립적으로 상품취득·결제후 추가행동 등 검토 후보 생성
4. Review dashboard: 사람이 확인해야 할 짧은 구간만 제시

## 개인정보/보안 원칙

- DMSS/안시포스 비밀번호를 StoreGuard에 저장하지 않습니다.
- 원본 CCTV 영상은 v0.1에서 복제하지 않습니다.
- 수집된 거래/알림 데이터는 기본적으로 기기의 Room DB에만 저장합니다.
- 외부 서버/API로 자동 전송하는 코드는 v0.1에 없습니다.

## 설치 후 필요한 사용자 작업

1. StoreGuard Hub 설치 및 실행
2. 앱에서 **DMSS 알림 접근** 버튼 → StoreGuard 알림 접근 허용
3. 앱에서 **안시포스 화면 접근성** 버튼 → StoreGuard 접근성 서비스 허용
4. DMSS와 안시포스는 평소처럼 로그인 유지
5. 안시포스의 매출 목록 화면을 열어 거래가 StoreGuard에 나타나는지 확인
6. DMSS 알림을 실제 1건 발생시켜 StoreGuard에 이벤트가 나타나는지 확인
7. 실제 결제/이벤트 표본이 3건 이상 쌓이면 `자동 추천`으로 시간 오프셋을 확인

비밀번호, 카드번호, CCTV 계정정보를 개발자/ChatGPT에 전달할 필요가 없습니다.

## 안시포스 파서가 기대하는 데이터

화면 한 행에 다음 데이터가 표시되는 현재 UI를 기준으로 작성했습니다.

- 신용카드 등 결제구분
- 정상매출/취소 등 매출구분
- `YYYY-MM-DD`
- `HH:mm:ss`
- `1,700원` 형태의 금액

접근성 트리에서 이 정보가 텍스트 노드로 노출되지 않는 경우 실제 기기 진단 후 다른 수집 방식이 필요합니다. v0.1의 수집 로그가 이 여부를 확인하기 위한 장치입니다.

## Android Studio 빌드

- JDK 17
- Android SDK 35
- Gradle 8.9 권장

프로젝트를 Android Studio에서 열고 `app` 디버그 빌드를 실행합니다.

## GitHub Actions

`.github/workflows/android.yml`이 포함되어 있습니다. 저장소에 올리면 Actions가 단위 테스트와 debug APK 빌드를 수행하고 `StoreGuardHub-v0.1-debug` artifact를 생성합니다.
